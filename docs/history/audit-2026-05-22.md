## High (2)

H1. **`env` / `sudo BASH_ENV=<sensitive_file> bash -c …` wrapper bypass** — `hooks/block-secrets.py:915-926` (`_check_dangerous_env_prefixes`) interacting with the `env` wrapper handler at `hooks/block-secrets.py:782-795` and the main loop at `hooks/block-secrets.py:1500-1525`. `_check_dangerous_env_prefixes` runs against the raw `sub_cmd` before `_strip_wrappers` strips `env`/`sudo`; the anchored `^\w+=` regex doesn't match because of the `env ` prefix, and after wrapper stripping the `BASH_ENV=` assignment is silently consumed. Undoes the C2 fix shipped 2026-05-10 for this same class. Fix: restructure so `_check_dangerous_env_prefixes` runs against the post-wrapper-strip, post-prefix-strip form; add red-team tests covering `env`, `sudo`, `cd dir &&`, `nohup`, `setsid` prefixes across every `_DANGEROUS_ENV_VARS` entry.

**Resolved in v1.1.2 (commit `93ec0e2`)** — new `_strip_wrappers_with_env` captures `KEY=VAL` args consumed by env/sudo wrappers, and a unified `_check_all_dangerous_env_assigns` runs the direct-prefix regex plus the wrapper-capture check per sub-command. Bonus fix: `env -u NAME` two-token flag form (via `_ENV_VALUE_FLAGS`). Audit prediction revised — the cd-chained direct form (`cd dir && BASH_ENV=…`) was already caught by `_split_shell_commands` segmenting on `&&`; only the wrapper forms (env/sudo, with or without `cd && ` prefix) actually bypassed. 78-case `hooks/test_phase4_audit_fixes.py` suite (failing-first: 35/78 against the unchanged hook), 1209/1209 across 16 suites after fix.

H2. **PostToolUse hook returns `decision: "warn"`, likely not a valid current Claude Code output value** — `hooks/warn-secrets-output.py:266-279`. Current Claude Code PostToolUse schemas typically support `decision: "block"` or `hookSpecificOutput.additionalContext`. `"warn"` may be silently treated as no-op, meaning the warning never reaches the model. The PreToolUse hook uses the modern `hookSpecificOutput.permissionDecision: "ask"` shape correctly (`block-secrets.py:1390-1402`), so the PostToolUse hook may have been written against an older spec and never re-validated. Fix: verify against current Anthropic hook docs; if unsupported, migrate to `decision: "block"` with a reason, or `hookSpecificOutput: {hookEventName: "PostToolUse", additionalContext: "<warning>"}`. Add an end-to-end smoke test.

## Medium (8)

- M1 **`os.path.realpath()` on the hook critical path** (`hooks/block-secrets.py:405-422`) — every Bash/Read/Edit/Write tool call invokes it; can stall on network-mounted filesystems with no timeout. Fix: pre-filter with regex before realpath.
- M2 **Cross-project transcript reads with no opt-out** (`claude-approval-report.py:3434-3447` + `extract_user_prose`) — default behavior reads every JSONL under `~/.claude/projects/`. Add `--no-cross-project` flag and document privacy posture.
- M3 **`_check_dangerous_env_prefixes` misses `cd dir && BASH_ENV=…`** — same class as H1, different vector. Same structural fix covers both.
- M4 **`_extract_variable_names` regex narrowness** (`hooks/warn-secrets-output.py:198-201`) — only catches `\b\w+=\$\(`, missing backtick substitution, double-quoted substitution, heredoc input.
- M5 **`_classify_leak_confidence` underrates exposure for `curl -v` / `-vvv` / `2>&1`** (`hooks/block-secrets.py:443-454`) — these should bump confidence to "high".
- M6 **No global wall-clock budget on `git log` stability lookups in `--token-report`** (`claude-approval-report.py:1497-1522`). Per-call `lru_cache` + 2s timeout exists, but on a large finding set total wall time is unbounded.
- M7 **Audit-log default is opt-out, not opt-in** — README covers it but worth a first-run stderr hint.
- M8 **`--apply` tightens existing `settings.local.json` to `0o600`** without preserving prior mode or warning.

- I7 PostToolUse correctly does not log tool output.
- I8 Token attribution caps `cache_creation_input_tokens` share at `result_bytes/3` with `_token_estimate_method` tagging.
- I9 The three per-command checks (`_check_dangerous_env_prefixes`, `_check_command_secrets`, `_check_single_command_access`) see different pre-canonical forms of the same command because canonicalization steps (ANSI-C decode, heredoc strip, wrapper strip, prefix strip) are applied piecemeal rather than as a single pipeline. The H1 bypass is the first concrete consequence; the structural fix is a single canonicalization pass.

## Cross-cutting issue

I9 above is the architectural root cause behind H1 and M3 (and likely future bypasses in the same class). A unified canonicalization pass that produces a single `canonical_form` consumed by every downstream check would close the entire class.
